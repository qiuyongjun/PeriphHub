# 雷柏 VT1 Pro（VID 24AE / PID 1214）HID 协议笔记

所有结论均由抓包与真机读写验证得出，测试时的设备状态：电量 93%，7 档 DPI
`[400, 800, 1200, 1600, 3200, 6400, 26000]`，当前档位 1600（索引 3），回报率 1000 Hz，
静默高度 1.1 mm，移动同步开，防抖 8/8 ms，休眠 10 分钟，直线/波纹修正关闭。

## 1. 接口

两条独立的 HID collection，按 usage page / usage 区分，**不是同一个句柄**：

| 用途 | usage page | usage | report id | 报文长 |
| --- | --- | --- | --- | --- |
| 命令通道（读写配置） | `0xFF00` | `0x0E` | `0xBA` | 32 字节（含 RID，载荷 31） |
| 状态通道（被动上报） | `0xFF00` | `0x02` | `0xBB` | 6 字节 |

访问方式：SetupAPI 枚举 HID 接口 → `CreateFileW`(shared) → 用 `HidD_GetAttributes`
匹配 VID/PID、`HidP_GetCaps` 匹配 usage page/usage。传输用
`HidD_SetOutputReport` / `HidD_GetInputReport`（控制传输），不是重叠 I/O 的 ReadFile。
官方程序会同时打开两个句柄（抓包里是 `0x85c` 写、`0x860` 读）。

## 2. 命令帧

```
请求  BA A5 <op> <len> <addr LE32> <data...>          共 32 字节，data 最多 24 字节
应答  <status> [1..] ...                               读数据在 [4 .. 4+len]
```

| op | 含义 | 说明 |
| --- | --- | --- |
| `0xA4` | 读 | `len` 字节，地址任意（无需对齐） |
| `0xA5` | 写 | **必须 4 字节对齐**，`len` = 4 或更少，写完不生效 |
| `0xA3` | 提交 | 让写入落到 EEPROM，应答形如 `01 7d` |
| `0xAA` | 电量 | 应答 `[1]` = flag(1)，`[2]` = 百分比 |
| `0xB0` | 接收器信息 | 未细究 |

应答首字节：`1` = OK，`2` = busy，其它 = 错误。写入流程是
读 4 字节块 → 改字节 → 写回整块 → `0xA3` 提交（官方程序同样是 4 字节对齐 RMW）。

## 3. 时序（最容易踩坑的部分，务必照做）

1. 发命令后设备**立即**回 `status=2`，再回 `status=1` 和真正的数据；busy 有时候观察不到。
2. **读命令可能被吞**：设备不回新应答时，`HidD_GetInputReport` 会重复返回**上一条**
   应答（buffer 不会清零）。只按 `status==1` 取数会读到过期数据 —— 表现为「移动同步
   莫名变关、LOD 变 1.0」，因为 0x0884 读回的是之前 0x0880 的应答。
   解决：发命令后记下**上一条应答的 `[1..]`**，只有「与它不同」才算新应答。
3. 忙期间读到的仍是旧应答，因此收到新应答后至少再等 **40 ms** 才接受。
4. **命令之间至少隔 15 ms**：实测间隔过小时丢包率约 25%，加 15 ms 后 30 秒 37 次读
   0 丢包、0 错值。
5. 读命令 **400 ms** 没有新应答 → 原样重发一次（一次足够，重发基本都成）。写/提交
   用 200 ms 预算。
6. 空闲（如每 4 秒轮询一次）之后第一条命令可能要 **150–250 ms** 才回，不要按短超时判定失败。
7. 官方程序节奏约 50 ms/命令，busy→ready 100–150 ms。
8. 两个程序同时轮询同一设备会互相读到对方的应答（共享应答 buffer）。做验证时先关掉面板。

## 4. EEPROM 映射（地址均为绝对地址）

| 地址 | 长度 | 含义 |
| --- | --- | --- |
| `0x0004` | 2 | 接收器 PID（实测 `0x4414`） |
| `0x0600` / `0x0618` / `0x0630` | - | 按键映射块 |
| `0x0880` | 1 | 回报率间隔 ms：`1`=1000、`2`=500、`4`=250、`8`=125 Hz |
| `0x0884` | 1 | 静默高度 LOD，编码 = mm×10−9：`1`=1.0 … `11`=2.0（实测 2 = 1.1 mm） |
| `0x0885` | 1 | 移动同步 0/1 |
| `0x0886` | 1 | 恒为 1，用途未知 |
| `0x0888` | 14 | DPI X，7×u16 LE |
| `0x0896` | 1 | 档位数 − 1（7 档时为 6） |
| `0x0898` | 1 | 当前档位索引（0 基） |
| `0x08C0` / `0x08C1` | 1 / 1 | 按下 / 抬起防抖 ms |
| `0x08C2` | 1 | 休眠等待分钟 |
| `0x08C3` | 1 | 修正开关，**反向**：bit0=1 表示直线修正关闭，bit1=1 表示波纹修正关闭 |
| `0x08C4` | 2 | 疑似角度，写 1 后界面无变化，**未验证** |
| `0x08C8` | 14 | DPI Y，7×u16 LE；与 X 保持一致，改 DPI 时两块都要写 |

`0x0880` 整块读 4 字节会带回 `0x0881..0x0883`（实测 `01 00 01 ff`），`0x0884` 整块为
`02 01 01 00`，`0x08C0` 起 4 字节为 `08 08 0a 03`（防抖按下/抬起/休眠/修正位）。

## 5. 状态通道 0xBB（未使用，留作备查）

约每 3 秒一帧被动上报，例：`B0 51 40 06 01 5D`

- `[2..4]` = DPI LE（`40 06` = 1600）
- `[4]` = 回报率标志
- `[5]` = 电量百分比（`5D` = 93）

如果以后想让面板零轮询（避免占用 2.4G 链路），可以改为订阅这一路：DPI、电量、
回报率都能免费拿到，配置项再按需读。

## 6. 未解决

- `0x08C4` 角度编码：写 1 后官方界面无变化，暂未纳入界面。
- 2000/4000 Hz：该接收器 `8k` 能力为 false，只支持 125–1000 Hz，界面未列。
- `0x0886`、`0x089A` 语义未知。
- 精确的 busy 上报规律（什么情况下不发 busy）未完全摸清，靠第 3 节的容错兜住。

## 7. 最小验证客户端

```python
import ctypes, time
hid = ctypes.WinDLL("hid.dll")
k32 = ctypes.WinDLL("kernel32", use_last_error=True)
k32.CreateFileW.restype = ctypes.c_void_p

# path: 由 hidapi.enumerate(0x24AE, 0x1214) 里 usage_page==0xFF00 and usage==0x0E 取出
h = ctypes.c_void_p(k32.CreateFileW(path, 0x80000000 | 0x40000000, 3, None, 3, 0, None))

def xfer(op, addr=0, data=b"", prev=b"\0" * 31, read=None):
    frame = [0xBA, 0xA5, op, len(data)] + list(addr.to_bytes(4, "little")) + list(data)
    buf = (ctypes.c_ubyte * 32)(*frame, *([0] * (28 - len(data))))
    assert hid.HidD_SetOutputReport(h, buf, 32)
    t0 = time.perf_counter()
    while time.perf_counter() - t0 < 0.4:
        rb = (ctypes.c_ubyte * 32)()
        rb[0] = 0xBA
        if hid.HidD_GetInputReport(h, rb, 32) and rb[0] == 1:
            if time.perf_counter() - t0 >= 0.040 and (read is None or bytes(rb[1:]) != prev):
                time.sleep(0.015)          # 命令间隔
                return bytes(rb)
        time.sleep(0.002)
    raise RuntimeError("no answer")
```

读 0x0880 会得到 `01 00 01 ff`，读 0x0884 得到 `02 01 01 00`，可用来对照。
