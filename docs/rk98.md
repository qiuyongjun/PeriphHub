# RK98 / 接收器 25A7:FA70 —— 实测笔记（结论：2.4G 下无法读写）

2026-10-31 在本机（Windows 11）实测，键盘为 RK98，2.4G 模式。接收器
product string 为 `2.4G Wireless Receiver`、厂商 `Compx`——和狼蛛 F87 的接收器
（`3554:FA09`）是同一家 ODM，但**通道布局完全不同**。

## 1. 接口

复合设备两个功能，共 8 个 HID 集合：

| 集合 | usage page / usage | 报文 | 说明 |
| --- | --- | --- | --- |
| `MI_00` | `0x01` / `0x06` | in 9 / out 2 | 键盘（boot），out 是 LED 报告 |
| `MI_01&COL01` | `0x01` / `0x02` | in 8 | 鼠标（接收器兼容鼠标） |
| `MI_01&COL02` | `0xFF01` / `0x0000` | **in 8，out 0** | 厂商输入通道，report id `0x02` |
| `MI_01&COL03..05` | `0x01` / `0x06` | in 8 | 键盘（NKRO / 多媒体层） |
| `MI_01&COL06` | `0xFF02` / `0x0002` | **feature 8，in/out 0** | 8 字节静态记录，report id `0x06` |
| `MI_01&COL07` | `0x0C` / `0x01` | in 3 | Consumer |
| `MI_01&COL08` | `0x01` / `0x0080` | in 2 | System Control |

对比 F87：那边的控制通道是 `0xFF02`/`0x02` 的 **20 字节 in/out** 集合（`0x13` 帧）。
这里的 `0xFF02` 只有 8 字节 **feature**，没有中断端点。

## 2. 为什么说"写不了"

三层证据，缺一层都可能误判：

1. **没有输出端点。** `HidP_GetCaps` 对两个厂商集合的 `OutputReportByteLength`
   都是 0，`SetOutputReport` 无从下手；整个设备唯一能写的是键盘 LED 报告
   （`MI_00` 的 out 2 字节），与配置无关。
2. **唯一的可写字节没有应答。** `0xFF02` 的 feature 记录里只有 byte1 可写：

   ```
   读回：06 00 02 00 00 00 31 3E
   写   06 4A 02 00 00 00 31 3E  →  读回 06 4A 02 00 00 00 31 3E
   ```
   依次用 `0x4A`（F87 游社区验证过的电量查询）、`0x44`（读配置）、`0x41`、`0x42`
   写这个字节，同时监听 `0xFF01` 输入通道 **各 700 ms，一帧都没有**。
   这个字节更像"命令锁存"，但没有回值通道，等于只能按下不能读表。
   已把 byte1 写回 `0x00` 复原（现在读回与初始值一致）。
3. **被动监听也没有数据。** 在 `0xFF01` 上连续监听 **90 秒**（正常打字使用期间），
   **0 帧**。所以它连"按键状态/电量推送"都不发。

## 3. 结论

2.4G 模式下 RK98 只能被**识别**：面板显示 RK、RK98、2.4G 和连接状态，
参数区换成一句解释（见 `driver::SUPPORTED` 总表里的 `reason`）。
电量、灯效、休眠、按键映射一概读不到——不是面板没做，是这条链路上没有可用的通道。

## 4. 还想支持的话

按代价从低到高：

1. **有线模式重测。** 拔掉接收器、用 USB 线直连键盘，看是否出现新的厂商集合
   （带 out 端点、或 64 字节 feature）。RK 系键盘的配置通常只走有线通道。
   探针现成：`cargo run --example probe -- 25a7`（VID 可能变成键盘本体，先全量枚举一次）。
2. **抓官方软件。** RK 的配置软件如果走 WebHID / 自有 HID，抓一次写入就能拿到完整帧格式，
   但这需要有线通道先存在。
3. 不要在这个接收器上继续猜命令：唯一可写的字节已经试过，没有任何回值。

## 5. 复现

```bash
cargo run --example probe -- 25a7     # 枚举集合、caps、feature 记录，并监听 6 秒厂商输入
```

`probe` 现在会监听**所有** `0xFFxx` 且有输入报表的集合（之前只监听 `0xFF02`），
F87 那种 20 字节通道与这里这种 8 字节通道都能一并看到。
