# 与雷柏官方驱动的功能差距对照

> 状态：**A 组已实现**（2026-10-31）：任意档 DPI 直接输入、系统指针速度/滚轮行数。
> 其余各组仍待决策。

本文把本机安装的雷柏官方驱动（RapooGameDev）和当前 PeriphHub 逐项比对，列出**还没做**的功能，
并给出协议依据、工作量与风险，供决定是否实现。

## 0. 参考资料从哪来

| 来源 | 内容 |
| --- | --- |
| `C:\Program Files (x86)\Rapoo\RapooGameDev` | 官方驱动的 Qt 界面资源，提取出全部界面文案（设置项名称、功能说明、报错提示） |
| `%LOCALAPPDATA%\RapooGameDev\config\VT1PRO HSDM\默认配置.json` | 官方对 VT1 Pro（`24AE:1214`）的**配置字段全表**，是设备能力的权威清单 |
| `%LOCALAPPDATA%\RapooGameDev\AppConfig.ini` | 官方支持的机型 PID：`17428 / 17456 / 4628 / 4656`（4628 = VT1 Pro） |
| `docs/protocol.md` | 本项目已实测的 EEPROM 地址表 |

官方这份默认配置的关键字段（就是设备真实存在的功能面）：

```
dpi{dpiValue[{currentValue, enable}]}   key[{funcIndex, key}]   report{index}   reportDongle{index}
motionSyn  straightLine  corrugation  sensorAngle  silentHeight  sleepTime
keyDownDelay  keyUpDelay  openDPIXY  glassFunc  support8k  fwVersion
```

## 1. 官方程序的功能地图

官方是"一个设备 = 5 个页签 + 4 个全局模块"：

- **设备概况**：当前档位、电量、连接模式、固件版本、指针速度/滚轮速度
- **配置设置**：多套配置文件的新建/重命名/删除、上传/下载云配置
- **DPI 设置**：7 档数值、每档启用开关、X/Y 轴独立 DPI
- **按键设置**：单按键 / 组合键 / 宏按键，功能表覆盖鼠标键、多媒体、系统快捷键、DPI 切换、回报率切换、宏切换、禁用
- **参数设置**：回报率、移动同步、直线修正、波纹修正、按下/抬起防抖、休眠、静默高度、传感器角度、玻璃追踪、8000Hz
- **全局**：宏编辑、灯光（本机型无灯）、OLED（本机型无屏）、方案共享/云同步、固件升级、对码工具、恢复出厂、检查更新、语言切换

## 3. 未实现项的技术评估

按"协议清楚度 × 工作量"排序，这才是决定要不要做的依据。

| 功能 | 协议依据 | 工作量 | 风险 |
| --- | --- | --- | --- |
| 每档 DPI 直接输入 | 已有 `0x0888 + i*2`，只需加输入框/编辑器 | 小 | 无 |
| X/Y 轴独立 DPI | `0x0888`(X) 与 `0x08C8`(Y) 已分开读，官方 `openDPIXY` 是一个开关位 | 小（开关位要在 EEPROM 里找） | 找不准开关位就只能做"永久独立"，没有总开关 |
| 每档启用/禁用 | 官方 `enable` 字段，推测在 `0x089A` 附近（未验证） | 中 | 猜地址会写坏配置，需要先扫描 + 备份 |
| 有线/无线回报率分开 | 官方 `report` 与 `reportDongle` 两个 index | 中 | 需要分别在有线、无线两种接法下抓包对比 |
| 传感器角度 | `0x08C4` 写 1 后官方界面无变化，未验证编码 | 中 | 可能误伤传感器参数 |
| 玻璃追踪 | `glassFunc`，对应一个标志位（位置未知） | 中 | 同上 |
| 指针/滚轮速度 | 与设备无关，走 `SystemParametersInfo` | 小 | 无 |
| 恢复出厂 | 官方是重写整块配置 | 中 | 误操作会清掉用户设置，需要二次确认 + 先导出备份 |
| 按键自定义 | 按键块已知，`funcIndex` 表需要靠抓包 + 逐个试 | **大** | 写错按键会让鼠标按键失灵，需可回滚 |
| 宏 | 依赖按键自定义 | **大** | 同上，且要新增文件格式与编辑器 |
| 固件升级 / 对码 | 官方是独立进程 + USB 复合设备流程 | **大** | 砖机风险，不建议自研 |
| 多配置文件 | 纯本地 JSON，不碰设备 | 小–中 | 无（只是产品取舍：PeriphHub 现在是"所见即所改"，加配置会让模型复杂） |

## 4. 建议（给决策用）

- **已完成**：1、14 —— 成本低、用户天天用得上，且不碰未验证地址。
- **可以做但要先探针**：2、3、4 —— 都要先确定一个 EEPROM 位或一段映射，建议先用 `examples/probe` 扫一遍再动手。
- **谨慎**：11、12、15 —— 都是"改错会静默影响手感"的项，如果没有真机对照官方界面验证，宁可先不做。
- **不建议自研**：21、22 —— 固件升级和对码涉及 USB 复合设备与砖机风险，官方已经提供了独立工具。
- **纯产品取舍**：19 多配置文件 —— PeriphHub 的定位是"改完即生效、没有保存概念"，加配置档会削弱这个特点。
- **价值最低**：26、27、28 —— 托盘电量数字、多语言、检查更新，属于锦上添花。
